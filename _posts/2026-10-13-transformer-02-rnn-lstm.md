[Attention Is All You Need](/posts/attention-is-all-you-need/) 글에서 "RNN은 멀리 있는 단어를 잊는다"고 한 줄로 넘어갔다. 이 편은 그 한 줄을 풀어보는 글이다. 왜 잊는지를 수식으로 따라가 보고, LSTM이 그걸 어떻게 줄였는지, 그래도 왜 트랜스포머가 필요했는지까지 이어간다.

시리즈 1부의 두 번째 편이다. 이전 편은 [#1 단어 임베딩](/posts/transformer-01-word-embedding/), 다음 편은 [#3 Seq2Seq와 최초의 어텐션](/posts/transformer-03-seq2seq-attention/)이다. 미분의 연쇄법칙을 들어본 정도면 읽을 수 있게 썼다.

## 한 문장 정의와 요약

RNN은 단어를 하나씩 읽을 때마다 같은 가중치로 "지금까지의 요약"을 덮어쓰는 모델이고, LSTM은 그 요약 옆에 덧셈으로 이어지는 별도의 기억 통로를 둔 RNN이다.

기억할 건 세 가지다. 첫째, RNN이 잊는 건 학습 신호(기울기)가 같은 값을 여러 번 곱하며 거꾸로 전달되기 때문이다. 둘째, LSTM은 기억을 곱셈이 아니라 덧셈으로 이어 붙여서 신호가 덜 깎이게 했다. 셋째, 그래도 한 단어씩 순서대로 읽는 구조는 그대로라서 병렬화가 안 되고, 이게 트랜스포머가 풀려던 문제다.

## 왜 필요한가

문장은 순서가 있는 데이터다. "개가 사람을 물었다"와 "사람이 개를 물었다"는 같은 단어로 이뤄졌지만 뜻이 반대다. 그래서 단어 벡터([#1](/posts/transformer-01-word-embedding/)에서 다룬 임베딩)를 그냥 더하거나 평균 내면 순서가 사라진다.

가장 자연스러운 해법은 사람처럼 앞에서부터 읽는 것이다. 단어 하나를 읽을 때마다 "지금까지 읽은 내용"을 갱신하고 다음 단어로 넘긴다. 이게 RNN(Recurrent Neural Network, 순환 신경망)이다. 문장 길이가 5든 500이든 같은 가중치를 반복해서 쓰니까 입력 길이에 제한도 없다.

문제는 학습할 때 생긴다. 문장 끝에서 틀린 답을 냈다면, 그 책임이 문장 앞쪽 단어에도 전달돼야 앞쪽 처리가 개선된다. 그런데 RNN에서는 이 책임 신호가 앞으로 갈수록 거의 사라진다. 다음 절이 그 이유다.

## 작동 원리

### RNN: 같은 가중치로 계속 덮어쓴다

RNN의 은닉 상태 갱신식은 한 줄이다.

```
h_t = tanh( W_h · h_{t-1} + W_x · x_t + b )

h_t     : t번째 단어까지 읽은 요약 (은닉 상태)
x_t     : t번째 단어 벡터
W_h, W_x: 모든 단계가 공유하는 가중치
```

펼쳐 그리면 이렇다. 같은 상자가 단어 수만큼 이어진다.

```
 x_1        x_2        x_3              x_T
  │          │          │                │
  ▼          ▼          ▼                ▼
[RNN] ──▶ [RNN] ──▶ [RNN] ──▶ ... ──▶ [RNN] ──▶ 출력 → 오차
  h_1        h_2        h_3              h_T
        (모든 상자가 같은 W_h, W_x를 쓴다)
```

### 기울기가 사라지는 이유: 같은 값의 거듭제곱

학습은 출력의 오차를 거꾸로 전달하면서 가중치를 고친다. 시간 축으로 펼친 RNN에 역전파를 적용한다고 해서 BPTT(Backpropagation Through Time)라고 부른다.

문장 끝 h_T의 오차가 k번째 단계 h_k까지 얼마나 전달되는지는 연쇄법칙으로 구한다.

```
∂h_T     ∂h_T      ∂h_{T-1}         ∂h_{k+1}
───── = ──────── · ────────── · ... · ────────
∂h_k    ∂h_{T-1}   ∂h_{T-2}           ∂h_k
```

한 단계짜리 미분은 갱신식에서 바로 나온다. tanh 안쪽을 a_t라고 하면 이렇다.

```
∂h_t / ∂h_{t-1} = tanh'(a_t) · W_h
```

이걸 T-k번 곱한다. 이해하기 쉽게 숫자 하나짜리(1차원) RNN으로 줄이면 식이 이렇게 된다.

```
∂h_T / ∂h_k = (w · tanh'(a_{k+1})) × (w · tanh'(a_{k+2})) × ... × (w · tanh'(a_T))
```

같은 w가 T-k번 곱해진다. 여기서 두 가지가 정해진다.

- tanh의 미분은 항상 1 이하다(입력이 0일 때 최댓값 1). 그래서 곱해지는 값 하나하나가 w보다 크지 않다.
- 곱해지는 값이 계속 1보다 작으면 결과는 거듭제곱으로 0에 다가간다. 0.9를 50번 곱하면 0.005다. 이게 기울기 소실(vanishing gradient)이다.
- 반대로 비선형 함수 없이 w가 1보다 크면 거듭제곱으로 커진다. 1.1을 50번 곱하면 117이다. 이게 기울기 폭주(exploding gradient)다.

실제 RNN은 숫자가 아니라 행렬이라 w 대신 W_h의 가장 큰 고윳값이 이 역할을 한다. Pascanu 등(2013)은 tanh를 쓸 때 W_h의 가장 큰 고윳값이 1보다 작으면 먼 단계의 기울기가 사라지기에 충분하고, 폭주하려면 1보다 커야 한다는 조건을 보였다.

![RNN과 LSTM의 기울기 흐름](/assets/img/posts/transformer-02-rnn-lstm/01.gif)
_오차 신호가 앞 단계로 거슬러 가며 RNN은 깎이고, LSTM 셀 상태는 유지된다 (값은 실제 계산)_

GIF의 숫자는 w = 0.9, 입력 0.1로 실제 계산한 값이다. 8단계짜리 짧은 문장인데도 RNN은 맨 앞(h1)에 0.18만 도착한다. LSTM의 셀 상태 경로는 0.93이 도착한다.

### LSTM: 기억을 덧셈으로 잇는다

LSTM(Long Short-Term Memory)은 은닉 상태 h 옆에 셀 상태 c라는 기억 통로를 하나 더 둔다. 그리고 이 통로에 무엇을 지우고, 무엇을 쓰고, 무엇을 꺼낼지를 게이트 세 개가 정한다. 게이트는 0~1 사이 값을 내는 시그모이드(σ)라서 "얼마나 열지"를 뜻한다.

```
f_t = σ( W_f · [h_{t-1}, x_t] + b_f )     forget 게이트: 기억에서 얼마나 남길까
i_t = σ( W_i · [h_{t-1}, x_t] + b_i )     input 게이트 : 새 정보를 얼마나 쓸까
g_t = tanh( W_g · [h_{t-1}, x_t] + b_g )  후보 정보   : 쓸 내용
o_t = σ( W_o · [h_{t-1}, x_t] + b_o )     output 게이트: 기억에서 얼마나 꺼낼까

c_t = f_t ⊙ c_{t-1} + i_t ⊙ g_t           셀 상태 갱신 (⊙ = 원소별 곱)
h_t = o_t ⊙ tanh(c_t)                     은닉 상태 = 꺼낸 기억
```

![LSTM 게이트의 동작](/assets/img/posts/transformer-02-rnn-lstm/02.gif)
_forget 게이트가 지우고, input 게이트가 쓰고, output 게이트가 꺼낸다 (게이트 값은 설명용 예시)_

핵심은 c_t 식이다. RNN은 이전 상태를 행렬에 곱하고 tanh에 통과시켜 새 상태를 만든다. LSTM의 셀 상태는 이전 기억에 f_t를 곱하고 새 정보를 더할 뿐이다. 이걸 미분하면 이렇게 된다.

```
∂c_t / ∂c_{t-1} = f_t        (셀 상태를 직접 잇는 경로)

∂c_T / ∂c_k = f_{k+1} × f_{k+2} × ... × f_T
```

곱해지는 게 W_h나 tanh 미분이 아니라 forget 게이트 값 자체다. 그리고 이 값은 모델이 학습으로 정한다. "이 정보는 계속 들고 가야 한다"고 배우면 f를 1에 가깝게 열어두고, 그러면 기울기가 그 통로를 따라 거의 그대로 흘러간다. 이 덧셈 통로를 흔히 셀 상태 고속도로라고 부른다.

정확히 말하면 게이트들도 h_{t-1}에 의존하니까 기울기가 흐르는 경로가 이것 하나만은 아니다. 그래도 장거리 기억을 지키는 건 이 직접 경로고, LSTM 설계의 요점도 여기에 있다.

### 그래도 남는 한계

LSTM은 기울기 문제를 많이 줄였다. 하지만 구조는 여전히 RNN이다.

```
            순서대로 기다려야 하는 단계 수     첫 단어 → 마지막 단어 경로 길이
RNN/LSTM    n                                n
트랜스포머   1                                1
```

h_t를 계산하려면 h_{t-1}이 있어야 하니 단어 수만큼 한 줄로 기다려야 한다. GPU가 아무리 많아도 한 문장 안에서는 병렬로 돌릴 수 없다. 그리고 문장 처음 정보가 끝까지 가려면 여전히 n단계를 거쳐야 한다. 게이트가 깎임을 줄여줄 뿐 경로 자체가 짧아지진 않는다.

여기서 나온 질문이 "단계를 거치지 말고 필요한 단어를 바로 보면 안 되나?"다. 이게 다음 편의 어텐션이고, 결국 트랜스포머로 이어진다.

## 실제로 계산해보기

식만 보면 잘 와닿지 않아서 직접 돌려봤다. numpy 없이 파이썬 표준 라이브러리만 썼다.

먼저 `h_t = tanh(w·h_{t-1} + 0.1)`로 갱신하는 1차원 RNN에서 처음 상태까지 기울기가 얼마나 남는지 계산한다. 비교용으로 tanh가 없는 선형 RNN의 w^T도 같이 찍었다.

```python
import math

def rnn_grad(w, T, x=0.1, h0=0.0):
    """1차원 RNN h_t = tanh(w*h_{t-1} + x)에서 dh_T/dh_0를 연쇄법칙으로 계산"""
    h, grad = h0, 1.0
    for _ in range(T):
        h = math.tanh(w * h + x)
        grad *= w * (1 - h * h)      # dh_t/dh_{t-1} = w * tanh'(.)
    return grad

print(f"{'T':>4} | {'w=0.5':>10} {'w=0.9':>10} {'w=1.1':>10} | {'선형 1.1^T':>10}")
for T in [1, 5, 10, 20, 50]:
    row = [rnn_grad(w, T) for w in (0.5, 0.9, 1.1)]
    print(f"{T:>4} | " + " ".join(f"{g:>10.2e}" for g in row) + f" | {1.1**T:>10.2f}")
```

```
   T |      w=0.5      w=0.9      w=1.1 |   선형 1.1^T
   1 |   4.95e-01   8.91e-01   1.09e+00 |       1.10
   5 |   2.73e-02   4.05e-01   8.38e-01 |       1.61
  10 |   7.05e-04   7.61e-02   8.79e-02 |       2.59
  20 |   4.67e-07   1.55e-03   2.62e-04 |       6.73
  50 |   1.36e-16   1.10e-08   5.97e-12 |     117.39
```

w = 0.9면 20단계 만에 0.0016, 50단계면 0.00000001이다. 50단어짜리 문장은 흔한데, 첫 단어 쪽은 사실상 아무것도 배우지 못한다는 뜻이다.

내가 가장 흥미로웠던 건 w = 1.1 열이다. 선형이었다면 117배로 폭주했을 텐데, tanh를 넣으니 오히려 0으로 사라졌다. w가 크면 h 값이 커져 tanh가 포화되고(값이 ±1 근처에 붙고), 포화된 tanh의 미분은 0에 가깝기 때문이다. tanh는 폭주를 어느 정도 막아주는 대신 소실 쪽으로 몰아간다. 실제 행렬 RNN에서는 두 현상이 다 일어나서 폭주 대책(기울기 클리핑)도 따로 필요하다.

다음은 LSTM 셀 상태의 직접 경로다. 앞에서 유도한 대로 forget 게이트 값 f를 T번 곱하면 된다.

```python
# LSTM 셀 상태 c_t = f*c_{t-1} + i*g 의 직접 경로 기울기 dc_T/dc_0 = f^T
print(f"{'T':>4} | {'f=0.5':>10} {'f=0.9':>10} {'f=0.99':>10} {'f=1.0':>10}")
for T in [1, 5, 10, 20, 50]:
    print(f"{T:>4} | " + " ".join(f"{f**T:>10.2e}" for f in (0.5, 0.9, 0.99, 1.0)))
```

```
   T |      f=0.5      f=0.9     f=0.99      f=1.0
   1 |   5.00e-01   9.00e-01   9.90e-01   1.00e+00
   5 |   3.12e-02   5.90e-01   9.51e-01   1.00e+00
  10 |   9.77e-04   3.49e-01   9.04e-01   1.00e+00
  20 |   9.54e-07   1.22e-01   8.18e-01   1.00e+00
  50 |   8.88e-16   5.15e-03   6.05e-01   1.00e+00
```

f = 0.99면 50단계 뒤에도 0.6이 남는다. 같은 50단계에서 RNN(w = 0.9)은 1.1e-08이었다. 차이가 7자리 이상이다.

그런데 f = 0.9 열을 보면 50단계에 0.005로, RNN과 비슷하게 사라진다. LSTM이라서 자동으로 오래 기억하는 게 아니라, 게이트가 1에 가깝게 열려 있을 때만 오래 기억한다는 뜻이다. 실무에서 forget 게이트의 편향(b_f)을 1처럼 큰 값으로 초기화하는 관행이 있는 이유도 이것이다. 학습 초반부터 통로를 열어두려는 것이다.

## 흔한 오해

LSTM이 기울기 소실을 해결했다는 말은 반만 맞다. 위 표에서 봤듯이 forget 게이트가 0.9만 돼도 50단계면 신호가 0.005로 줄어든다. LSTM은 모델이 "이건 오래 들고 가자"고 배울 수 있는 통로를 만들어준 것이지, 모든 정보를 오래 기억하게 만든 게 아니다. 수백 단어 넘게 떨어진 의존성은 LSTM도 여전히 어려워한다.

처음 LSTM 논문에 forget 게이트가 있었다는 것도 오해다. 1997년 Hochreiter와 Schmidhuber의 원 논문에는 input 게이트와 output 게이트만 있었고, 셀 상태는 지워지지 않고 계속 더해지기만 했다. forget 게이트는 Gers 등이 2000년에 추가했다. 지금 우리가 LSTM이라고 부르는 건 대부분 이 개선판이다.

LSTM이 기울기 폭주까지 막아준다고 생각하기 쉽다. 셀 상태 경로는 f ≤ 1이라 그 경로로는 폭주하지 않지만, 게이트와 은닉 상태를 거치는 다른 경로가 있어서 폭주는 여전히 생길 수 있다. 그래서 RNN 계열 학습에는 보통 기울기 클리핑(기울기 크기가 정해진 값을 넘으면 잘라내기)을 같이 쓴다.

RNN이 짧은 문장만 처리할 수 있다는 것도 정확하지 않다. 입력 길이에는 제한이 없다. 긴 문장을 넣어도 계산은 된다. 안 되는 건 학습이다. 먼 단어 사이의 관계를 배우는 신호가 도착하지 않아서, 결과적으로 가까운 단어 위주로만 배운다.

## 요약

RNN은 같은 가중치로 요약을 계속 덮어쓴다. 그래서 학습 신호가 거꾸로 갈 때 같은 값이 거듭 곱해지고, 1보다 작으면 사라지고 크면 폭주한다. LSTM은 셀 상태를 덧셈으로 이어서 forget 게이트 값만 곱해지게 만들었고, 게이트가 열려 있으면 신호가 오래 살아남는다.

개인적으로 이 편을 정리하면서 가장 크게 바뀐 생각은 이거다. LSTM이 고친 건 "깎이는 정도"였고, 트랜스포머가 고친 건 "거쳐야 하는 길이"였다. 앞의 것은 게이트를 잘 학습시키는 문제고, 뒤의 것은 구조를 바꾸는 문제다.

다음 편 [#3 Seq2Seq와 최초의 어텐션](/posts/transformer-03-seq2seq-attention/)에서는 RNN 두 개를 이어 번역기를 만든 Seq2Seq와, 문장 전체를 벡터 하나에 담아야 했던 병목을 어텐션이 어떻게 풀었는지 본다.

## 학습 확인 질문

1. RNN에서 먼 단계의 기울기가 사라지는 이유를 한 단계 미분식으로 설명하면?

   답: 한 단계 미분은 tanh'(a_t)·W_h이고, 먼 단계까지의 기울기는 이것을 단계 수만큼 곱한 값이다. tanh'는 1 이하라서 곱해지는 값이 계속 1보다 작으면 결과가 거듭제곱으로 0에 가까워진다.

2. LSTM 셀 상태의 직접 경로에서 기울기가 덜 깎이는 이유는?

   답: c_t = f_t ⊙ c_{t-1} + i_t ⊙ g_t라서 ∂c_t/∂c_{t-1} = f_t다. 곱해지는 값이 고정된 행렬과 tanh 미분이 아니라 학습되는 forget 게이트 값이므로, 게이트가 1에 가깝게 열려 있으면 기울기가 거의 그대로 전달된다.

3. LSTM이 있는데도 트랜스포머가 필요했던 구조적 이유 두 가지는?

   답: 첫째, h_t가 h_{t-1}에 의존하므로 문장 안에서 단어들을 병렬로 계산할 수 없다. 둘째, 첫 단어 정보가 마지막 단어까지 가려면 여전히 n단계를 거쳐야 해서 경로 길이가 O(n)이다.
