트랜스포머 그림을 보면 맨 아래에 `Input Embedding`이라는 상자가 있다. 어텐션도, 위치 인코딩도 전부 이 상자가 내놓은 벡터 위에서 일어난다. 그런데 "단어를 벡터로 바꾼다"는 게 정확히 무슨 뜻인지는 대개 한 줄로 넘어간다. 이 글은 그 한 줄을 풀어본다.

이 글은 「트랜스포머 깊게 보기」 시리즈의 첫 편이다. 전체 지도는 [Attention Is All You Need](/posts/attention-is-all-you-need/)에 있고, 다음 편은 [#2 RNN과 LSTM](/posts/transformer-02-rnn-lstm/)이다.

대상 독자는 벡터와 내적이 뭔지 아는 정도의 사람이다. 예제는 전부 numpy 없이 순수 파이썬으로 돌렸고, 실제 출력을 그대로 실었다.

## 한 문장 정의와 요약

단어 임베딩은 단어 하나를 수백 개의 실수로 이뤄진 벡터로 바꾸되, 의미가 비슷한 단어일수록 벡터의 방향도 비슷해지도록 학습한 표현이다.

기억할 건 세 가지다. 첫째, 단어마다 칸 하나를 주는 one-hot 방식은 모든 단어를 서로 남남으로 만든다. 둘째, "비슷한 문맥에 나오는 단어는 의미도 비슷하다"는 가정 하나로 벡터를 학습할 수 있다. 셋째, 트랜스포머의 입력 임베딩도 같은 아이디어지만, 미리 만든 벡터를 가져다 쓰지 않고 모델과 함께 처음부터 학습한다.

## 왜 필요한가: one-hot의 한계

컴퓨터에게 단어를 주는 가장 단순한 방법은 번호를 매기는 것이다. 단어장에 단어가 4개 있으면 4칸짜리 벡터를 만들고, 자기 번호 칸에만 1을 넣는다. 이게 one-hot이다.

```
         왕  여왕  남자  고양이
왕     [ 1,   0,   0,    0 ]
여왕   [ 0,   1,   0,    0 ]
남자   [ 0,   0,   1,    0 ]
고양이 [ 0,   0,   0,    1 ]
```

문제는 두 가지다.

첫째, 크다. 단어장 크기가 곧 벡터 차원이다. 트랜스포머 논문의 영어-독일어 실험은 약 37,000개 토큰짜리 단어장을 썼다. one-hot이면 단어 하나가 37,000차원 벡터고, 그중 36,999칸이 0이다.

둘째, 더 치명적인 문제다. 서로 다른 두 one-hot 벡터의 내적은 항상 0이다. 1이 있는 칸이 겹치지 않으니까. 그러면 "왕"과 "여왕"의 유사도와 "왕"과 "고양이"의 유사도가 똑같이 0이 된다. 모델 입장에서는 모든 단어가 서로 똑같이 무관하다.

내가 이 글에서 one-hot부터 시작하는 이유가 여기 있다. 임베딩이 해결하는 문제는 "단어를 숫자로 바꾸기"가 아니다. 그건 one-hot도 한다. 진짜 문제는 "단어 사이의 관계를 숫자에 담기"다.

## 작동 원리

### 해결책: 짧고 촘촘한 벡터

방향을 바꿔보자. 단어마다 칸을 하나씩 주는 대신, 모든 단어가 같은 몇 개의 축을 공유하고 각 축에 실수 값을 갖게 한다. 이해를 돕기 위해 축에 이름을 붙이면 이런 모양이다.

```
          왕족   남성   여성   동물
왕     [ 0.92, 0.85, 0.12, 0.03 ]
여왕   [ 0.90, 0.11, 0.87, 0.04 ]
남자   [ 0.12, 0.88, 0.10, 0.06 ]
여자   [ 0.10, 0.08, 0.91, 0.05 ]
고양이 [ 0.05, 0.40, 0.42, 0.95 ]
```

이제 "왕"과 "여왕"은 왕족 축을 공유하니 내적이 0이 아니다. 이런 벡터를 밀집 벡터(dense vector), 또는 분산 표현(distributed representation)이라고 부른다. 의미가 한 칸에 몰려 있지 않고 여러 축에 흩어져 있다는 뜻이다.

![emb-onehot-to-dense](/assets/img/posts/transformer-01-word-embedding/01.gif)
_one-hot에서는 모든 단어가 똑같이 떨어져 있고, 학습한 밀집 벡터에서는 비슷한 단어끼리 모인다_

물론 실제로는 사람이 축을 정하지 않는다. 축의 개수(트랜스포머는 512)만 정하고 값은 학습으로 채운다. 그러면 무엇을 기준으로 학습하나.

### 단서: 주변 단어

언어학에는 오래된 가정이 있다. 단어의 뜻은 그 단어와 함께 나오는 단어들이 정한다는 것이다(분포 가설). 이런 문장들을 보자.

```
나는  고양이를  키운다
나는  강아지를  키운다
고양이에게  밥을  준다
강아지에게  밥을  준다
왕이   나라를   다스린다
```

"고양이"와 "강아지"는 앞뒤에 오는 단어가 거의 같다. "키운다", "밥을" 같은 단어 옆에 나온다. 반면 "왕"은 "다스린다" 옆에 나온다. 주변 단어만 보고도 고양이와 강아지가 같은 부류라는 걸 짐작할 수 있다.

2013년 구글의 Mikolov 연구진이 발표한 Word2Vec은 이 가정을 학습 문제로 바꿨다. 그중 Skip-gram 방식은 가운데 단어 하나를 보고 주변 단어를 맞히게 한다. "고양이를"을 보고 "키운다"가 근처에 나올 확률을 높이는 식이다.

### 왜 문맥이 같으면 벡터가 가까워지나

이 부분을 한 번 유도해보자. Skip-gram은 가운데 단어 벡터 `v`와 문맥 단어 벡터 `u`의 내적이 클수록 "같이 나올 확률이 높다"고 본다. 확률로 바꾸는 데 시그모이드 `σ`를 쓰면 이렇다.

```
P(같이 나옴) = σ(v · u)
```

학습은 실제로 같이 나온 쌍의 `log σ(v · u)`를 키우는 방향으로 `v`를 조금씩 움직인다. 이걸 `v`로 미분하면 다음과 같다.

```
∂/∂v  log σ(v · u)  =  (1 - σ(v · u)) · u
```

오른쪽 식을 보면 `v`가 움직이는 방향은 항상 `u` 쪽이다. 앞의 `(1 - σ)`는 0과 1 사이의 수라서 얼마나 크게 움직일지만 정한다.

여기서 결론이 나온다. "고양이"와 "강아지"가 둘 다 "키운다" 옆에 자주 나오면, 두 벡터는 학습할 때마다 같은 `u_키운다` 방향으로 끌려간다. 같은 방향으로 계속 끌려가니 결국 서로 가까워진다. 사람이 "고양이와 강아지는 비슷하다"고 알려준 적이 없는데도 그렇게 된다.

(이 σ 형태는 같은 연구진의 후속 논문에서 나온 네거티브 샘플링 방식을 단순화한 것이다. 실제로는 같이 나오지 않은 단어를 밀어내는 항도 함께 쓴다. 여기서는 끌어당기는 쪽만 보였다.)

### 관계가 방향으로 남는다

이렇게 학습한 공간에서 Mikolov 연구진이 보여준 유명한 결과가 있다. `왕 - 남자 + 여자`를 계산하면 그 결과 벡터에 가장 가까운 단어가 `여왕`이라는 것이다.

이유는 위의 유도에 이미 들어 있다. 남자와 여자가 나오는 문맥의 차이, 왕과 여왕이 나오는 문맥의 차이가 비슷하다면, 그 차이는 벡터 공간에서 비슷한 화살표로 남는다. `여자 - 남자`가 "성별을 바꾸는 방향"이 되고, 그 화살표를 왕에 더하면 여왕 근처에 도착한다.

![emb-analogy](/assets/img/posts/transformer-01-word-embedding/02.gif)
_남자에서 여자로 가는 화살표를 왕에서 출발시키면 여왕 근처에 도착한다_

## 실제로 계산해보기

### 1. 코사인 유사도와 벡터 산술

위 표의 4차원 벡터로 직접 계산해봤다. 유사도는 코사인 유사도를 쓴다. 두 벡터의 내적을 각자의 길이로 나눈 값으로, 방향이 같으면 1, 직각이면 0이다.

```python
import math

def cos(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return dot / (na * nb)

# one-hot: 단어 4개 → 4차원
onehot = {
    "왕":   [1, 0, 0, 0],
    "여왕": [0, 1, 0, 0],
    "남자": [0, 0, 1, 0],
    "고양이": [0, 0, 0, 1],
}
print("[one-hot]")
print("왕-여왕  ", round(cos(onehot["왕"], onehot["여왕"]), 3))
print("왕-고양이", round(cos(onehot["왕"], onehot["고양이"]), 3))

# 밀집 벡터: 축 = [왕족, 남성, 여성, 동물] (설명용으로 직접 정한 값)
emb = {
    "왕":     [0.92, 0.85, 0.12, 0.03],
    "여왕":   [0.90, 0.11, 0.87, 0.04],
    "남자":   [0.12, 0.88, 0.10, 0.06],
    "여자":   [0.10, 0.08, 0.91, 0.05],
    "고양이": [0.05, 0.40, 0.42, 0.95],
}
print("\n[밀집 벡터]")
print("왕-여왕  ", round(cos(emb["왕"], emb["여왕"]), 3))
print("왕-남자  ", round(cos(emb["왕"], emb["남자"]), 3))
print("왕-고양이", round(cos(emb["왕"], emb["고양이"]), 3))

# 왕 - 남자 + 여자
v = [k - m + w for k, m, w in zip(emb["왕"], emb["남자"], emb["여자"])]
print("\n왕 - 남자 + 여자 =", [round(x, 2) for x in v])
rank = sorted(emb, key=lambda w: cos(v, emb[w]), reverse=True)
for w in rank:
    print(f"  {w:<4} {cos(v, emb[w]):.3f}")
```

```
[one-hot]
왕-여왕   0.0
왕-고양이 0.0

[밀집 벡터]
왕-여왕   0.649
왕-남자   0.774
왕-고양이 0.332

왕 - 남자 + 여자 = [0.9, 0.05, 0.93, 0.02]
  여왕   0.998
  여자   0.790
  왕    0.603
  고양이  0.329
  남자   0.212
```

one-hot에서는 예상대로 전부 0이다. 밀집 벡터에서는 `왕 - 남자 + 여자`의 결과가 여왕과 0.998로 거의 같은 방향을 가리킨다.

그런데 출력에서 하나가 눈에 걸렸다. 왕과 여왕(0.649)보다 왕과 남자(0.774)가 더 비슷하게 나왔다. 계산이 틀린 게 아니다. 이 벡터에서는 성별 축 값이 크게 차이 나서, 왕족 축을 공유하는 것보다 성별 축을 공유하는 게 코사인 값에 더 크게 작용했다. 나는 이게 임베딩을 이해할 때 가장 중요한 감각이라고 본다. "비슷하다"는 하나의 기준이 아니라, 모든 축을 한꺼번에 섞은 결과다.

### 2. 문맥이 같으면 가까워지는지 확인

위에서 유도한 `v ← v + η · (1 - σ(v · u)) · u` 업데이트를 그대로 돌려봤다. 고양이와 강아지는 일부러 직각(코사인 0)에서 출발시키고, 둘 다 "키운다"의 문맥 벡터 쪽으로 20번 업데이트한다. 왕은 건드리지 않는다.

```python
import math

def cos(a, b):
    d = sum(x * y for x, y in zip(a, b))
    return d / (math.hypot(*a) * math.hypot(*b))

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

# 처음 벡터 (2차원, 일부러 서로 다른 방향에서 시작)
v = {"고양이": [1.0, 0.2], "강아지": [-0.2, 1.0], "왕": [0.6, -0.8]}
u_keep = [0.7, 0.7]   # 문맥 단어 "키운다"의 문맥 벡터

print("학습 전 cos(고양이, 강아지) =", round(cos(v["고양이"], v["강아지"]), 3))
print("학습 전 cos(고양이, 왕)     =", round(cos(v["고양이"], v["왕"]), 3))

lr = 0.3
for step in range(20):
    for w in ("고양이", "강아지"):          # 둘 다 "키운다" 옆에 나온다
        g = 1 - sigmoid(sum(a * b for a, b in zip(v[w], u_keep)))
        v[w] = [a + lr * g * b for a, b in zip(v[w], u_keep)]

print("학습 후 cos(고양이, 강아지) =", round(cos(v["고양이"], v["강아지"]), 3))
print("학습 후 cos(고양이, 왕)     =", round(cos(v["고양이"], v["왕"]), 3))
```

```
학습 전 cos(고양이, 강아지) = 0.0
학습 전 cos(고양이, 왕)     = 0.431
학습 후 cos(고양이, 강아지) = 0.765
학습 후 cos(고양이, 왕)     = 0.134
```

처음에는 고양이가 강아지(0.0)보다 왕(0.431)에 더 가까웠다. 같은 문맥 쪽으로 끌려간 뒤에는 순서가 뒤집혀 강아지와 0.765, 왕과 0.134가 됐다. 유사도를 직접 가르친 적은 없다. 같은 문맥을 공유했다는 사실만으로 이렇게 된다.

### 3. 트랜스포머의 입력 임베딩은 룩업 테이블이다

트랜스포머의 `Input Embedding` 상자는 `단어장 크기 × d_model` 모양의 행렬 하나다. 단어 번호가 들어오면 그 번호의 행을 꺼낸다. 이게 one-hot 벡터에 행렬을 곱한 것과 같다는 걸 확인해봤다.

```python
# 임베딩 룩업 = one-hot × 행렬
E = [  # 단어 4개 × 3차원 (값은 예시)
    [0.2, 0.7, -0.1],   # 0: 나는
    [0.5, -0.3, 0.8],   # 1: 고양이를
    [0.9, 0.1, 0.4],    # 2: 좋아한다
    [-0.6, 0.2, 0.3],   # 3: 어제
]
x = [0, 1, 0, 0]        # "고양이를"의 one-hot
row = [sum(x[i] * E[i][j] for i in range(4)) for j in range(3)]
print("one-hot × E =", row)
print("E[1]        =", E[1])
print("파라미터 수 (37000 × 512) =", 37000 * 512)
print("sqrt(512) =", round(512 ** 0.5, 2))
```

```
one-hot × E = [0.5, -0.3, 0.8]
E[1]        = [0.5, -0.3, 0.8]
파라미터 수 (37000 × 512) = 18944000
sqrt(512) = 22.63
```

one-hot을 곱한 결과와 1번 행이 똑같다. 그래서 실제 구현은 곱셈을 하지 않고 행을 바로 꺼낸다. one-hot은 개념으로만 남고 메모리에는 만들지 않는다.

논문 기준으로 이 행렬은 약 37,000 × 512, 파라미터로 약 1,894만 개다. 논문은 여기에 세 가지를 덧붙인다.

- 이 행렬은 미리 학습한 Word2Vec을 가져오지 않고, 번역 모델과 함께 처음부터 학습한다.
- 인코더 입력 임베딩, 디코더 입력 임베딩, 출력 직전의 선형 변환이 같은 가중치 행렬을 공유한다.
- 임베딩 층에서는 가중치에 √d_model(= √512 ≈ 22.63)을 곱한다.

마지막 항목의 이유는 논문에 적혀 있지 않다. 흔히 나오는 해석은, 바로 다음에 더할 위치 인코딩 값이 -1에서 1 사이라서 임베딩 값이 너무 작으면 위치 정보에 묻히니 크기를 맞춰준다는 것이다. 나도 이 해석이 그럴듯하다고 보지만, 논문 저자가 밝힌 이유는 아니라는 점은 짚어둔다.

## 흔한 오해

임베딩의 각 축에 "왕족", "성별" 같은 의미가 붙어 있다는 오해가 있다. 이 글의 표는 설명하려고 축에 이름을 붙인 것이다. 실제로 학습된 512개 축은 하나하나가 사람이 읽을 수 있는 의미를 갖지 않는다. 의미는 축 하나가 아니라 방향 전체에 퍼져 있다.

`왕 - 남자 + 여자 = 여왕`이 항상 깔끔하게 된다는 것도 반만 맞다. 실제 Word2Vec 벡터에서 결과 벡터에 가장 가까운 단어를 그냥 찾으면 입력 단어인 `왕` 자체가 나오는 일이 흔하다. 그래서 gensim의 `most_similar`는 입력으로 준 단어를 결과에서 빼고 돌려준다(소스 코드에 "ignore (don't return) keys from the input"이라고 적혀 있다). 위 예제에서도 입력 단어 `여자`와 `왕`이 2, 3위에 있었다.

비슷한 벡터가 같은 뜻이라는 것도 아니다. 분포 가설은 "같은 문맥에 나온다"만 본다. "뜨겁다"와 "차갑다"는 반대말이지만 "물이 ___"처럼 같은 자리에 나오니 벡터가 가깝게 학습되기 쉽다. 같은 이유로 학습 데이터의 편견도 그대로 들어간다. 2016년 연구는 Word2Vec 벡터에서 `남자 : 프로그래머 = 여자 : 주부` 같은 성별 고정관념이 나온다는 걸 보였다.

트랜스포머가 단어 하나에 벡터 하나를 쓴다는 것도 정확하지 않다. 입력 임베딩 단계에서는 맞다. "배"라는 토큰은 문장과 상관없이 늘 같은 행에서 나온다. 하지만 어텐션 층을 지나면서 주변 단어 정보가 섞이고, 먹는 배와 타는 배가 서로 다른 벡터가 된다. Word2Vec 같은 정적 임베딩과 트랜스포머 내부의 문맥 임베딩을 구분하는 지점이 여기다. 그리고 트랜스포머가 다루는 단위는 단어가 아니라 서브워드 토큰이다. 논문은 BPE와 word-piece로 단어를 쪼갠 단어장을 썼다.

## 요약

one-hot은 단어를 숫자로 바꾸지만 모든 단어를 남남으로 만든다. 임베딩은 단어를 짧고 촘촘한 벡터로 바꾸고, 같은 문맥에 나오는 단어끼리 같은 방향으로 끌려가게 학습해서 관계를 담는다. 트랜스포머의 입력 임베딩도 같은 원리의 룩업 테이블이고, 모델과 함께 처음부터 학습된다.

다음 편은 이 벡터들을 문장 순서대로 읽던 방식, RNN과 LSTM이다. 단어를 하나씩 읽으면 왜 멀리 있는 단어를 잊는지, LSTM의 게이트가 그걸 어디까지 막아주는지 본다.

## 학습 확인 질문

1. one-hot 표현에서 서로 다른 두 단어의 코사인 유사도가 항상 0인 이유는?

   답: one-hot 벡터는 단어마다 서로 다른 칸 하나에만 1이 있다. 두 벡터에서 1이 있는 칸이 겹치지 않으니 내적이 0이고, 코사인 유사도도 0이 된다.

2. Skip-gram 학습에서 같은 문맥 단어 옆에 자주 나오는 두 단어의 벡터가 가까워지는 이유는?

   답: `log σ(v · u)`를 `v`로 미분하면 `(1 - σ(v · u)) · u`가 되어, 업데이트 방향이 항상 문맥 벡터 `u` 쪽이다. 두 단어가 같은 `u`를 공유하면 둘 다 같은 방향으로 끌려가서 서로 가까워진다.

3. 트랜스포머의 입력 임베딩 층이 하는 일을 행렬 연산으로 설명하면?

   답: `단어장 크기 × d_model` 행렬에 토큰의 one-hot 벡터를 곱해 해당 행을 꺼내는 것과 같다. 실제 구현은 곱셈 없이 토큰 번호로 행을 바로 꺼내고, 논문은 그 값에 √d_model을 곱한다.
