ChatGPT, Claude, Gemini가 전부 같은 뿌리에서 나왔다는 말을 들으면 결국 이 논문으로 돌아오게 된다. 2017년 구글 연구진 8명이 쓴 「Attention Is All You Need」다. 나도 대학원 수업에서 이 논문을 처음 읽었는데, 그림 한 장(Figure 1)과 수식 한 줄은 외웠지만 "그래서 Q, K, V가 뭔데?"라는 질문에는 대답을 못 했다. 이 글은 그 질문에 답하려고 다시 정리한 결과물이다.

대상 독자는 딥러닝을 조금 들어봤고 행렬 곱이 뭔지 아는 정도의 사람이다. RNN을 몰라도 읽을 수 있게 썼다.

## 한 문장 정의와 요약

트랜스포머는 문장 속 모든 단어가 다른 모든 단어를 한 번에 쳐다보고, 누구에게 얼마나 집중할지 스스로 정해서 자기 의미를 갱신하는 모델이다.

기억할 건 세 가지다. 첫째, 단어를 순서대로 하나씩 읽던 RNN을 버리고 전부 동시에 처리한다. 둘째, "누구에게 집중할지"는 내적(dot product)으로 계산한 유사도로 정한다. 셋째, 순서 정보가 사라지는 문제는 위치 인코딩이라는 별도 장치로 메운다.

## 왜 필요했나: RNN의 두 가지 한계

트랜스포머 이전 번역 모델의 주류는 RNN(LSTM, GRU)이었다. RNN은 문장을 사람이 읽듯 앞에서부터 한 단어씩 읽는다. 단어를 하나 읽을 때마다 "지금까지 읽은 내용 요약"(은닉 상태)을 갱신하고, 그걸 다음 단어로 넘긴다.

```
RNN: 한 단어씩, 앞 단계가 끝나야 다음 단계 시작

 나는 ──▶ [h1] ──▶ 어제 ──▶ [h2] ──▶ 산 ──▶ [h3] ──▶ 책을 ──▶ [h4] ──▶ 읽었다 ──▶ [h5]
          │                  │                │                 │                  │
          └── 요약을 계속 덮어쓰며 전달 (전화기 게임과 비슷)
```

여기서 문제가 두 개 생긴다.

첫째는 느리다는 것이다. h3을 계산하려면 h2가 있어야 하고, h2를 계산하려면 h1이 있어야 한다. GPU는 수천 개 계산을 동시에 하는 데 강한데, RNN은 구조상 한 줄로 서서 기다려야 한다. 문장이 100단어면 100단계를 순서대로 밟는다.

둘째는 멀리 있는 단어를 잊는다는 것이다. 문장 끝에서 첫 단어 정보가 필요하면 그 정보는 은닉 상태를 수십 번 거쳐 와야 한다. 전화기 게임처럼 중간에 흐려진다. LSTM이 이걸 많이 줄였지만 근본적으로 경로가 길다는 사실은 그대로다.

![RNN은 한 단계씩 기다리고, 셀프 어텐션은 한 번에 계산한다](/assets/img/posts/attention-is-all-you-need/01.gif)
_RNN은 한 단계씩 기다리고, 셀프 어텐션은 한 번에 계산한다_

사실 어텐션 자체는 2014~2015년에 이미 나와 있었다(Bahdanau 어텐션). 다만 RNN에 덧붙이는 보조 장치였다. 이 논문의 주장은 제목 그대로다. 보조 장치였던 어텐션만으로 충분하니 RNN을 아예 빼자.

## 핵심 아이디어: 셀프 어텐션

이런 문장을 보자.

```
The animal didn't cross the street because it was too tired.
```

여기서 `it`은 무엇일까. 사람은 바로 `animal`이라고 안다. tired(피곤한)는 동물에 어울리지 거리에 어울리지 않으니까. 모델도 `it`의 의미를 정하려면 문장 속 다른 단어를 둘러봐야 한다. 셀프 어텐션은 이걸 모든 단어에 대해 동시에 한다.

![it이 문장 전체를 둘러보며 집중도를 정한다](/assets/img/posts/attention-is-all-you-need/02.gif)
_it이 문장 전체를 둘러보며 집중도를 정한다_

(숫자는 설명용 예시값이다.)

RNN과 비교하면 차이가 분명하다. RNN에서 `it`이 `animal`을 참고하려면 6단계를 거쳐야 하지만, 셀프 어텐션에서는 한 단계로 바로 연결된다. 그리고 `it`이 둘러보는 동안 `tired`도, `street`도 동시에 각자 둘러본다. 순서대로 기다릴 이유가 없으니 GPU로 한 번에 계산한다.

## Q, K, V: 도서관 검색으로 이해하기

내가 가장 오래 막혔던 부분이 여기다. 논문에는 Query, Key, Value라는 세 단어가 나오는데, 도서관 검색에 비유하면 깔끔하게 정리된다.

| 이름 | 도서관 비유 | 셀프 어텐션에서 |
|---|---|---|
| Query (Q) | 내가 검색창에 친 검색어 | "나는 지금 이런 정보가 필요해" |
| Key (K) | 각 책에 붙은 색인 태그 | "나는 이런 정보를 갖고 있어" |
| Value (V) | 책의 실제 내용 | "선택되면 내가 넘겨줄 내용" |

검색어(Q)와 태그(K)가 잘 맞는 책일수록 그 내용(V)을 많이 가져온다. 이게 전부다.

헷갈리는 지점은 셀프 어텐션에서는 Q, K, V가 모두 같은 문장에서 나온다는 것이다. 단어 하나의 임베딩 벡터 `x`에 서로 다른 가중치 행렬 세 개를 곱해서 만든다.

```
             ┌──▶ × W_Q ──▶ q  (이 단어가 찾는 것)
 단어 벡터 x ─┼──▶ × W_K ──▶ k  (이 단어가 광고하는 것)
             └──▶ × W_V ──▶ v  (이 단어가 실제로 줄 정보)
```

같은 단어인데 왜 세 개로 나누나. 역할이 다르기 때문이다. `it`이 "나는 앞에 나온 명사 중 살아있는 걸 찾고 있어"(Q)라고 묻는 것과, `it`이 다른 단어에게 "나는 대명사야"(K)라고 알리는 것은 다른 정보다. W_Q, W_K, W_V는 학습으로 정해진다. 사람이 "대명사"나 "명사" 같은 규칙을 넣어주지 않는다.

## 작동 원리: 수식 한 줄을 손으로 풀어보기

논문의 핵심 수식은 이것이다.

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

네 단계로 쪼개면 이렇다.

```
① Q·Kᵀ        검색어와 모든 태그의 내적 → "얼마나 맞나" 점수
② ÷ √d_k      점수 크기 조절 (이유는 다음 절)
③ softmax     점수를 합이 1인 비율로 변환 → 집중도
④ × V         집중도만큼 각 단어의 내용을 섞음 → 새 표현
```

①이 내적인 이유는 간단하다. 두 벡터의 내적은 방향이 비슷할수록 크다. 선형대수에서 내적을 "한 벡터를 다른 벡터에 투영한 길이"로 봤던 것과 같은 직관이다. 방향이 비슷하다는 건 "찾는 것과 가진 것이 맞는다"는 뜻이다.

숫자로 직접 풀어보자. 단어 3개(`animal`, `street`, `it`)가 있고 벡터 차원은 2라고 하자. `it`의 새 표현을 계산한다.

```
it의 Query     q_it     = [2, 1]

Key            k_animal = [2, 1]
               k_street = [0, 1]
               k_it     = [1, 1]

Value          v_animal = [1, 0]
               v_street = [0, 1]
               v_it     = [0.5, 0.5]
```

① 내적 점수

```
q_it · k_animal = 2×2 + 1×1 = 5
q_it · k_street = 2×0 + 1×1 = 1
q_it · k_it     = 2×1 + 1×1 = 3
```

② √d_k = √2 ≈ 1.414로 나눈다

```
[5, 1, 3] / 1.414 = [3.54, 0.71, 2.12]
```

③ softmax (각 값에 e^x를 취하고 합으로 나눈다)

```
e^3.54 ≈ 34.3,  e^0.71 ≈ 2.0,  e^2.12 ≈ 8.3,  합 ≈ 44.7

집중도 = [0.77, 0.05, 0.19]
          animal street  it
```

④ 집중도로 Value를 섞는다

```
0.77 × [1, 0] + 0.05 × [0, 1] + 0.19 × [0.5, 0.5]
= [0.86, 0.14]
```

`it`의 새 벡터 `[0.86, 0.14]`는 `v_animal`인 `[1, 0]`에 가깝다. "it은 animal을 가리킨다"는 정보가 벡터에 섞여 들어간 것이다. 네 단계를 한 번에 보면 이렇다.

![수식 한 줄을 네 단계로 풀어본 과정](/assets/img/posts/attention-is-all-you-need/03.gif)
_수식 한 줄을 네 단계로 풀어본 과정_

실제 모델에서는 이 계산을 모든 단어가 동시에 하고, 행렬 곱 한 번으로 처리된다.

## 왜 √d_k로 나누나

수식에서 가장 사소해 보이는 부분인데, 논문이 이걸 "Scaled" Dot-Product Attention이라고 이름 붙일 만큼 신경 썼다.

벡터 차원 d_k가 커지면 내적값도 커진다. 평균 0, 분산 1인 값으로 이뤄진 벡터 두 개를 내적하면 결과의 분산이 d_k가 된다. 표준편차로는 √d_k다. 직접 시뮬레이션해보면 이렇다.

| d_k | 내적값의 표준편차 (실측) | 이론값 √d_k |
|---|---|---|
| 4 | 약 2.0 | 2 |
| 64 | 약 7.9 | 8 |
| 512 | 약 23 | 22.6 |

점수가 [8, 0, -8]처럼 크게 벌어지면 softmax 결과는 [0.9997, 0.0003, 0.0000]이 된다. 사실상 하나만 1이고 나머지는 0이다. 이 상태에서는 기울기가 거의 0이라 학습이 안 된다. √d_k(=8)로 나누면 [1, 0, -1]이 되고 softmax 결과는 [0.67, 0.24, 0.09]다. 여러 단어를 골고루 고려할 여지가 생긴다.

![d_k가 커질 때 나누지 않으면 softmax가 한쪽으로 쏠린다](/assets/img/posts/attention-is-all-you-need/04.gif)
_d_k가 커질 때 나누지 않으면 softmax가 한쪽으로 쏠린다_

논문의 기본 모델은 d_k = 64를 쓰므로 실제로 8로 나눈다.

## 멀티헤드 어텐션: 여러 관점으로 동시에 보기

어텐션을 한 번만 하면 `it`은 "누구를 가리키나"라는 한 가지 관점만 보게 된다. 그런데 문장에는 관점이 여러 개다. 주어-동사 관계, 수식 관계, 시제 등.

그래서 논문은 어텐션을 8개 병렬로 돌린다. 이걸 헤드(head)라고 부른다.

```
               입력 (512차원)
                    │
   ┌──────┬──────┬──┴───┬──────┬─── ... ───┐
   ▼      ▼      ▼      ▼      ▼           ▼
 head1  head2  head3  head4  head5  ...  head8     각 64차원
 (지시)  (주술)  (수식)   ...                        각자 다른 W_Q, W_K, W_V
   │      │      │      │      │           │
   └──────┴──────┴──┬───┴──────┴─── ... ───┘
                    ▼
            이어 붙이기 (64 × 8 = 512)
                    ▼
               × W_O (512 → 512)
                    ▼
                  출력
```

(괄호 안의 "지시", "주술" 같은 역할 이름은 이해를 돕기 위한 예시다. 각 헤드가 무엇을 볼지는 학습이 정하고, 사람이 지정하지 않는다.)

512차원을 통째로 한 번 쓰는 대신 64차원 8개로 쪼개서 쓰니, 계산량은 단일 헤드와 비슷하게 유지된다. 공짜로 관점을 8개 얻는 셈이다.

## 위치 인코딩: 순서를 잃어버린 문제

셀프 어텐션에는 치명적인 약점이 하나 있다. 단어 순서를 모른다.

모든 단어가 모든 단어를 동시에 보니, "개가 사람을 물었다"와 "사람이 개를 물었다"가 어텐션 입장에서는 같은 단어 집합이다. RNN은 순서대로 읽으니 순서가 자동으로 들어갔지만, 트랜스포머는 그걸 버렸다.

해결책은 단어 벡터에 "몇 번째 자리인지"를 나타내는 벡터를 더하는 것이다. 논문은 사인·코사인 함수로 만든다.

```
PE(pos, 2i)   = sin( pos / 10000^(2i/d_model) )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d_model) )

pos = 단어 위치, i = 벡터의 몇 번째 차원인지
```

수식은 무섭지만 아이디어는 시계와 같다. 초침, 분침, 시침은 각자 다른 속도로 돈다. 세 바늘 위치를 합치면 하루 중 어느 시각인지 유일하게 정해진다. 위치 인코딩도 차원마다 주기가 다른 파동을 써서, 앞쪽 차원은 빠르게(초침), 뒤쪽 차원은 느리게(시침) 바뀐다. 그 조합이 위치마다 고유한 지문이 된다.

![차원마다 주기가 다른 파동이 위치마다 고유한 지문을 만든다](/assets/img/posts/attention-is-all-you-need/05.gif)
_차원마다 주기가 다른 파동이 위치마다 고유한 지문을 만든다_

논문은 학습 가능한 위치 임베딩도 실험했는데 결과가 거의 같았다고 적었다. 사인·코사인을 고른 이유는 학습 때 본 것보다 긴 문장에도 적용할 수 있을 거라고 봤기 때문이다.

## 전체 구조: 인코더와 디코더

이제 부품이 다 모였다. 논문의 트랜스포머는 번역 모델이라 인코더(원문 이해)와 디코더(번역문 생성) 두 덩어리로 돼 있다.

![트랜스포머 전체 구조](/assets/img/posts/attention-is-all-you-need/07.png)
_트랜스포머 전체 구조 (출처: Vaswani et al., 2017, Figure 1)_

그림은 아래에서 위로 읽는다. 왼쪽 회색 상자가 인코더 한 층, 오른쪽 회색 상자가 디코더 한 층이고, 옆의 `N×`는 같은 층을 N번(논문은 6번) 쌓는다는 뜻이다. `Add & Norm`이 잔차 연결과 정규화다. 디코더 가운데 `Multi-Head Attention`으로 왼쪽에서 들어오는 선이 인코더 출력(K, V)이다. `Outputs (shifted right)`는 지금까지 생성한 번역문을 한 칸 밀어서 넣는다는 뜻으로, "I love you"를 번역하는 중이라면 `<시작> 나는 너를`이 들어가고 맨 위 `Softmax`가 다음 단어 "사랑해"의 확률을 낸다.

인코더 한 층은 두 부품이다. 셀프 어텐션으로 단어끼리 정보를 주고받고, Feed Forward 신경망으로 각 단어를 개별적으로 한 번 더 가공한다. 이걸 6층 쌓는다.

디코더에는 어텐션이 두 종류 있다.

마스크드 셀프 어텐션은 번역문을 만들 때 아직 안 만든 미래 단어를 못 보게 가린다. "나는 너를"까지 만든 상태에서 다음 단어를 예측하는데, 정답 "사랑해"를 미리 보면 커닝이 되기 때문이다. 구현은 softmax 직전에 미래 위치 점수를 -∞로 바꿔서 집중도를 0으로 만든다.

![미래 위치의 점수를 -∞로 덮어 커닝을 막는다](/assets/img/posts/attention-is-all-you-need/06.gif)
_미래 위치의 점수를 -∞로 덮어 커닝을 막는다_

인코더-디코더 어텐션은 디코더가 원문을 참고하는 통로다. Query는 디코더(지금 번역 중인 단어)에서, Key와 Value는 인코더 출력(원문)에서 온다. "사랑해"를 만들 때 원문의 "love"에 집중하는 식이다.

모든 부품 뒤에 붙은 "잔차연결 & 정규화"는 `LayerNorm(x + Sublayer(x))`다. 입력을 출력에 그대로 더해서(잔차 연결) 층이 깊어져도 정보와 기울기가 잘 흐르게 하고, 정규화로 값의 범위를 안정시킨다.

논문 기본 모델(base)의 주요 수치는 이렇다.

| 항목 | 값 |
|---|---|
| 인코더 / 디코더 층 수 | 각 6 |
| 모델 차원 d_model | 512 |
| 헤드 수 h | 8 |
| 헤드당 차원 d_k = d_v | 64 |
| Feed Forward 내부 차원 | 2048 |
| 드롭아웃 | 0.1 |

## 그래서 얼마나 좋아졌나

논문은 RNN, CNN, 셀프 어텐션을 층 하나 기준으로 비교한다. n은 문장 길이, d는 벡터 차원이다.

| 층 종류 | 층당 계산량 | 순차로 해야 하는 연산 수 | 먼 단어까지 경로 길이 |
|---|---|---|---|
| 셀프 어텐션 | O(n²·d) | O(1) | O(1) |
| RNN | O(n·d²) | O(n) | O(n) |
| CNN (커널 k) | O(k·n·d²) | O(1) | O(log_k(n)) |

읽는 법은 이렇다. 순차 연산 O(1)은 "기다릴 필요 없이 한 번에 병렬 계산"이라는 뜻이다. 경로 길이 O(1)은 "첫 단어와 마지막 단어가 한 단계로 연결"된다는 뜻이다. RNN의 두 한계를 정확히 겨냥한 결과다.

번역 성능도 당시 최고 기록을 갈아치웠다. WMT 2014 영어→독일어에서 BLEU 28.4, 영어→프랑스어에서 41.8을 기록했다(big 모델 기준). 학습 비용은 기존 최고 모델들의 일부 수준이었다. big 모델은 P100 GPU 8장으로 3.5일, base 모델은 12시간 걸렸다.

## 흔한 오해

트랜스포머가 어텐션을 발명했다는 오해가 많다. 어텐션은 이미 있었다. 이 논문의 기여는 RNN 없이 어텐션만으로 모델 전체를 만든 것과, 이를 위한 부품(스케일링, 멀티헤드, 위치 인코딩)을 조합한 설계다.

어텐션 가중치가 곧 모델의 "이유"라는 해석도 조심해야 한다. 위의 `it → animal` 같은 그림은 직관에 잘 맞지만, 헤드가 수십~수백 개이고 층이 깊어지면 개별 가중치가 모델 판단을 그대로 설명한다고 보기 어렵다. 설명용 시각화로 보는 게 맞다.

트랜스포머가 모든 면에서 효율적이라는 것도 반만 맞다. 위 표에서 셀프 어텐션의 계산량은 O(n²·d)다. 문장 길이가 2배가 되면 계산은 4배가 된다. 논문 당시 번역 문장은 짧아서 문제가 안 됐지만, 지금의 긴 컨텍스트 LLM에서는 이게 가장 큰 병목이다. FlashAttention 같은 후속 연구가 나온 이유다.

GPT가 이 논문 구조를 그대로 쓴다는 것도 정확하지 않다. GPT 계열은 디코더만 떼어서 쓰고(인코더-디코더 어텐션 없음), BERT는 인코더만 쓴다. 위치 인코딩도 지금은 RoPE 같은 다른 방식이 주로 쓰인다. 뼈대는 같고 부품은 많이 바뀌었다.

```
            Transformer (2017, 인코더 + 디코더)
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   인코더만           인코더 + 디코더     디코더만
   BERT (2018)        T5 (2019)          GPT 계열 (2018~)
   문장 이해·분류      번역·요약            텍스트 생성 (오늘날 LLM 대부분)
```

## 요약

RNN은 단어를 한 줄로 세워 읽어서 느리고 멀리 있는 단어를 잊었다. 트랜스포머는 모든 단어가 서로를 한 번에 보게 해서 두 문제를 동시에 풀었다.

그 "보는" 방법이 `softmax(QKᵀ/√d_k)V`다. 찾는 것(Q)과 가진 것(K)의 내적으로 집중도를 정하고, 그만큼 내용(V)을 섞는다. √d_k는 softmax가 한쪽으로 쏠리지 않게 막는다. 멀티헤드로 여러 관점을 동시에 보고, 위치 인코딩으로 잃어버린 순서를 되찾는다.

개인적으로는 손으로 3×2 행렬을 한 번 계산해본 뒤에야 이 수식이 외울 대상이 아니라 "검색"이라는 게 와닿았다. 이 글을 읽는 분도 위 예제 숫자를 바꿔서 직접 한 번 계산해보길 권한다.

다음에 읽어볼 만한 것은 디코더만 쓰는 GPT 구조와, n² 문제를 다루는 FlashAttention이다.

## 학습 확인 질문

1. 셀프 어텐션이 RNN보다 GPU에서 빠른 이유는 무엇인가?

   답: RNN은 이전 단어의 은닉 상태가 있어야 다음 단어를 계산할 수 있어 순차 처리가 강제된다. 셀프 어텐션은 모든 단어 쌍의 점수를 행렬 곱 한 번으로 동시에 계산하므로 순차 연산이 O(1)이다.

2. √d_k로 나누지 않으면 어떤 일이 생기나?

   답: d_k가 커질수록 내적값의 분산이 커져 softmax 출력이 한 단어에 거의 1로 쏠린다. 이 영역에서는 기울기가 0에 가까워 학습이 잘 되지 않는다.

3. 디코더의 셀프 어텐션에 마스크가 필요한 이유는?

   답: 학습 시 정답 문장 전체를 입력으로 넣는데, 마스크가 없으면 다음 단어(정답)를 미리 보고 예측하게 된다. 생성 시점과 같은 조건을 만들기 위해 미래 위치를 가린다.
